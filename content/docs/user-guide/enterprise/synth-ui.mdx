# Workspace Tour

Every board in Synth EE opens in the same workspace. This page walks through it once, from the top bar to the footer, so you know where each action lives.

![The board workspace](/screenshots/enterprise/05-workspace-pcb.png)

---

## The Shape of the Workspace

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Board name · revision · status      Command · New board · Export        │
├──────────────────────────────────────────────────────────────────────────┤
│ PCB │ Schematic │ 3D │ open tools…                         Details ▾     │
├────┬─────────────────────────────────────────────────┬───────────────────┤
│    │                                                 │                   │
│ R  │              Board canvas                       │   Design chat     │
│ A  │        PCB / Schematic / 3D / tool panel        │   Ask · patch     │
│ I  │                                                 │   · agent run     │
│ L  │                                                 │                   │
│    │                                                 │                   │
├────┴─────────────────────────────────────────────────┴───────────────────┤
│ phase · DRC status · size · layers · parts                               │
└──────────────────────────────────────────────────────────────────────────┘
```

- **Top bar** — identity and the three actions you use most.
- **View tabs** — **PCB**, **Schematic**, **3D**, plus a tab for every tool you open from the rail.
- **Design rail** — the tools. It is the fastest way to move around.
- **Canvas** — the board or the selected tool.
- **Design chat** — a conversation scoped to this board.
- **Footer** — the board's physical summary and the current check state.

---

## The Top Bar

| Control                   | What it does                                                                                                                |
| :------------------------ | :-------------------------------------------------------------------------------------------------------------------------- |
| **Board name**            | Takes you back to the workspace home.                                                                                       |
| **Revision badge**        | `v3` for a saved revision, `saved` when the source matches the saved revision, `draft` when there are unsaved edits.        |
| **Status pill**           | The current build state: **Queued**, **Placing**, **Routing**, **Checking DRC**, **Completed**, **Failed**, or **Blocked**. |
| **Command** (⌘K / Ctrl-K) | Opens the command palette: jump to a tool, run a build, validate the source, route, export, or start a new board.           |
| **New board**             | Opens the brief dialog.                                                                                                     |
| **Export**                | Opens the manufacturing export dialog.                                                                                      |

The command palette is the fastest path for keyboard users. Type a tool name, or type `build` and press Enter.

---

## The Design Rail

The rail is always visible while a board is open. Each icon opens a tool as a tab.

| Tool                    | Use it when you want to…                                                          |
| :---------------------- | :-------------------------------------------------------------------------------- |
| **Board**               | Return to the PCB view.                                                           |
| **Synth source**        | Read or edit the `.synth` source, check it, save it, or build it.                 |
| **Parts & BOM**         | Review every part, value, footprint, and supplier identity.                       |
| **Connections**         | Review every net, its pins, and the open connections.                             |
| **Architecture**        | Understand the design as functional groups, power rails, and signal nets.         |
| **Checks**              | Read compiler ERC, physical DRC, routing, and release evidence.                   |
| **Versions**            | Browse saved revisions and restore an earlier one.                                |
| **Placement & routing** | Set an explicit outline and run the router.                                       |
| **Sourcing**            | Look up a part by C-number or MPN and review the selected supplier.               |
| **Cost**                | Calculate a build cost and freeze procurement.                                    |
| **Delivery**            | Review manufacturing artifacts, attach an enclosure, and check release readiness. |
| **Project settings**    | Change the project name, description, and board-level settings.                   |
| **Generation activity** | Watch the live build log and stop a run.                                          |

Open as many tools as you need. Each one gets a tab, and the URL records the open tool so a link or a reload returns to the same place.

## The PCB View

![The PCB view with copper, silkscreen, pads, and airwires](/screenshots/enterprise/05-workspace-pcb.png)

The PCB view is the default. The layer bar above the canvas controls what is drawn:

| Control        | Shows                                                                          |
| :------------- | :----------------------------------------------------------------------------- |
| **All copper** | Every copper layer at once, with the front and back distinguished by colour.   |
| **Front**      | The front copper layer.                                                        |
| **Back**       | The back copper layer.                                                         |
| **Silk**       | Silkscreen reference designators and outlines.                                 |
| **Pads**       | Component pads, including through-hole and surface-mount pads.                 |
| **Airwires**   | The connections that are not yet routed. A fully routed board has no airwires. |

**Add part** opens the part picker. **Design preview** opens the board as a rendered preview rather than an editable canvas.

Selecting a component opens the inspector with its reference designator, value, footprint, and the nets it touches. Use the inspector to ask the chat about that component or to nudge its placement.

<Callout type="tip" title="The footer is a health check">

The footer repeats the information that matters: the phase or error, the DRC status, the board size, the layer count, and the part count. If the footer says **DRC not attested**, the export gate is not satisfied even if the status pill says **Completed**.

</Callout>

## The Schematic View

![The generated schematic](/screenshots/enterprise/12-schematic.png)

The schematic is generated from the source. It is a review view: you can select a component or a net and inspect it, but you do not draw wires here. To change the circuit, change the source.

The schematic and PCB share the same selection. Select `U2` in the schematic and the PCB highlights the same part, and the inspector opens on it.

---

## The 3D View

![The 3D board view](/screenshots/enterprise/13-3d.png)

The 3D view renders the board with its components from the generated KiCad project. Use it to check:

- Connector orientation and edge placement.
- Tall parts that might collide with an enclosure.
- Whether the board outline matches the mechanical design.

The 3D view is a render, not a mechanical simulation. Attach a STEP enclosure from **Delivery** if you need to review a real mechanical fit.

---

## The Design Chat

The chat panel on the right is scoped to the open board. It can answer questions about the design and, when a model provider is configured, propose source changes as patch cards.

| Action                        | What it does                                                                          |
| :---------------------------- | :------------------------------------------------------------------------------------ |
| **Ask**                       | Answers a question about the board, a component, or a finding.                        |
| **Review checks**             | Explains the current findings in plain language.                                      |
| **Summarize**                 | Gives a short summary of the board's function and state.                              |
| **Start a durable agent run** | Starts a longer design workflow on the server. It keeps running if you close the tab. |

A proposed patch shows the source diff and the affected placement. **Accept** validates the patch and saves it as a new revision. **Reject** leaves the board unchanged.

<Callout type="info" title="Chat needs a model provider">

The chat and agent features need an OpenAI-compatible or OpenRouter model configured by your administrator. If the panel says the assistant is unavailable, the rest of the workspace — source, builds, checks, routing, export — still works without it.

</Callout>

## The Source Tool

![The source editor with the problems panel](/screenshots/enterprise/06-source.png)

The source tool is a full editor for the `.synth` file.

| Control          | What it does                                                               |
| :--------------- | :------------------------------------------------------------------------- |
| **Check source** | Runs the compiler and fills **Problems**. Fast; does not change the board. |
| **Save draft**   | Saves the source as a new revision without building.                       |
| **Build board**  | Saves the source and starts a new physical build.                          |
| **Download**     | Downloads the source file.                                                 |

The **Problems** panel groups diagnostics by severity and shows the line, the code, and the suggested fix. The source is the only design input; treat the editor as the real file.

## Parts & BOM

![Parts and BOM](/screenshots/enterprise/09-parts-bom.png)

Every placed part appears here with its reference designator, quantity, value, footprint, and type. Use the filter to find a part by reference, value, or footprint.

The BOM export uses the same assignment. If a part has a supplier identity, it appears in the table; if it does not, the sourcing tools can help you choose one.

---

## Connections

![Connections and open nets](/screenshots/enterprise/10-connections.png)

The connections tool lists every net and the pins on it. The summary tells you whether any net is open.

- **No open nets reported** means every declared connection has copper.
- **Nets with missing connections** are listed with their pads and the reason the router could not connect them.

Select a net to highlight it on the PCB and in the schematic.

---

## Architecture

![Architecture view](/screenshots/enterprise/14-architecture.png)

Architecture turns the source's `group` blocks into a block diagram. It is the fastest way to understand a board someone else wrote:

- **Components** — the parts in each functional group.
- **Power / ground nets** — the rails and their loads.
- **Signal nets** — the connections between groups.

Use it before a review: if a group is missing a decoupling capacitor or a power rail is not where you expect it, the diagram makes it obvious.

---

## Checks

![Checks and diagnostics](/screenshots/enterprise/07-checks.png)

The Checks tool is the board's evidence page. It is covered in detail in [Builds, Checks, and Recovery](/user-guide/enterprise/agent-worker). The four cards are:

- **Compiler ERC** — source-level electrical checks.
- **Physical DRC** — the native KiCad rule check on the delivered copper.
- **Routing** — connectivity and router findings.
- **Release** — whether the revision can be exported.

---

## Versions

![Versions](/screenshots/enterprise/15-versions.png)

Every save or build creates a revision. The list shows the content hash, who created it, the parent revision, and the status. **Restore** creates a new revision from an earlier source; it does not delete history.

Use versions before a risky change. If the new build is worse, restore the previous revision and rebuild.

---

## Placement & Routing

![Placement and routing](/screenshots/enterprise/08-routing.png)

This tool does two things:

1. **Physical outline** — set an explicit width and height, then **Apply size & rebuild**.
2. **Placement & routing** — choose the router, passes, and threads, then **Run router & DRC**.

The source remains authoritative. An explicit size is a constraint passed to the placer, not a change to the `.synth` file.

---

## Sourcing and Cost

![Cost and sourcing](/screenshots/enterprise/16-cost.png)

The cost tool builds a reproducible cost report from the board's parts, quantities, layer count, and dimensions. It can show a target budget and a supplier quote when your deployment has a quote provider configured.

**Freeze procurement** records the exact part assignments for a manufacturing variant. Freeze before you request a quote, so the quote and the board refer to the same parts.

The sourcing tool looks up a part by LCSC C-number or manufacturer part number and shows the selected supplier identity.

---

## Delivery and Manufacturing

![Delivery and manufacturing](/screenshots/enterprise/17-delivery.png)

The delivery tool collects the artifacts a fabricator or assembler needs:

- The KiCad project and the routed board.
- Gerber and drill files.
- The BOM and pick-and-place file.
- The evidence bundle for this revision.
- An optional STEP enclosure, if you attach one.

**Release readiness** is the verdict. A package is ready only when the revision, checks, and evidence agree. The tool never promotes an unknown check to a pass.

---

## Project Settings

Project settings change the project's name and description and the board-level settings that the server owns. The `.synth` source still owns the electrical and physical declarations. If a setting changes the design, change it in the source and rebuild.

---

## Generation Activity

**Generation activity** is the live run view. It shows:

- The current step and status.
- The compiler and router output.
- The progress bar.
- **Stop** for a running build.
- **Check status** for the evidence page.

If a build fails, this is the first place to look. The log usually names the exact stage and the reason.
